PopDrop 0.10.0 cache stream-release fix
Package revision: cache-stream-release-fix-20260730
Preview helper protocol: 4

Evidence from the Windows cache-status.ini:

- Stage=Completed
- Attempted=17
- Succeeded=0
- Failed=17

Root cause:

The WIC encoder successfully committed its temporary output, but EncodeImage
then tried to reopen the same file for FlushFileBuffers while IWICStream still
held its exclusive file handle. The reopen failed with a sharing violation.
EncodeImage returned false and WriteCache deleted the already encoded temporary
file, causing every cache item to fail and leaving the directory empty.

Fix:

- Release the converter, property bag, frame, encoder, stream and bitmap COM
  chain after Commit.
- Only then reopen the temporary file and call FlushFileBuffers.
- Keep the AHK cache timeout/failure continuation diagnostics.
- Allow up to 50 successful new cache files per hidden session, with a hard
  limit of 100 attempts so failures do not consume the success allowance.

This package necessarily changes PopDropPreview.cpp. Rebuild:

powershell -ExecutionPolicy Bypass -File .\native\build.ps1

Then run PopDrop.ahk and verify:

cache\preview-cache-v1\
