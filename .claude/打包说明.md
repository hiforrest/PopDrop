# PopDrop 打包说明

## 概述

本文档说明如何将 PopDrop 编译并打包为面向最终用户的可分发版本。

**核心原则：发布包只包含运行程序所需的文件，不包含源码、测试、构建脚本等开发内容。**

## 发布包内容清单

```
PopDrop_v1.0.0.zip
├── PopDrop.exe              ← 主程序（x64，已编译独立 EXE）
├── config.example.ini       ← 配置示例（用户复制为 config.ini）
├── README.md                ← 项目介绍
├── USAGE.md                 ← 使用指南
├── CHANGELOG.md             ← 更新日志
├── THIRD_PARTY_NOTICES.md   ← 第三方许可声明
├── assets/
│   ├── app.ico              ← 主图标（编译版运行时需要）
│   ├── tray.ico             ← 托盘图标
│   └── logo.webp            ← README 用图
└── native/
    ├── install-pdfium.ps1   ← PDFium 可选安装脚本
    ├── pdfium-component.ini ← PDFium 组件配置
    ├── bin/x64/
    │   ├── PopDropTransfer.exe  ← 外部内容投放 Helper（x64）
    │   └── PopDropPreview.exe   ← 文件预览 Helper（x64）
    ├── bin/x86/
    │   ├── PopDropTransfer.exe  ← 外部内容投放 Helper（x86，源码模式）
    │   └── PopDropPreview.exe   ← 文件预览 Helper（x86，源码模式）
    └── third_party/pdfium/LICENSE  ← PDFium BSD 许可证
```

## 不打包的内容

| 类型 | 文件 | 原因 |
|------|------|------|
| AHK 源码 | `PopDrop.ahk`、`modules/*.ahk`、`ConfigDocument.ahk` 等 | 编译版用户不需要 |
| 构建脚本 | `BUILD.md`、`native/build.ps1`、`native/README.md` | 最终用户不构建 |
| 发布说明 | `RELEASE_NOTES_v1.0.0.md` | 内部版本记录，对外用 CHANGELOG |
| 开发文档 | `dev_doc/*` | 开发期文档 |
| 测试文件 | `tests/*`、`native/tests/*` | 最终用户不运行测试 |
| C++ 源码 | `native/PopDropTransfer/*.cpp`、`native/PopDropPreview/*.cpp` | 已提供二进制 |
| 本地配置 | `native/vs_path.txt` | 本机构建路径 |

## 编译步骤

### 1. 编译主程序

```powershell
# 删除旧 exe（避免残留）
Remove-Item 'PopDrop.exe' -ErrorAction SilentlyContinue

# 编译（必须使用 /base 参数指定 v2 解释器）
& 'C:\Program Files\AutoHotkey\Compiler\Ahk2Exe.exe' `
  /in 'PopDrop.ahk' `
  /out 'PopDrop.exe' `
  /icon 'assets\app.ico' `
  /base 'C:\Program Files\AutoHotkey\v2\AutoHotkey64.exe' `
  /compress 0
```

> **关键：必须使用 `/base` 参数指向 v2 的 `AutoHotkey64.exe`。** 不能依赖 Compiler 目录下的 `.bin` 存根文件，因为它们可能是 v1 版本。
>
> Ahk2Exe 根据 Base 文件的扩展名决定脚本嵌入方式：
> - `.exe` 后缀 → 脚本写入 `RCDATA #1` 资源，v2 解释器启动时自动加载
> - `.bin` 后缀 → 使用旧式资源名，v2 解释器无法识别
>
> 因此**不能把 `AutoHotkey64.exe` 改名为 `.bin` 使用**，编译出来的 EXE 会退化为普通解释器模式，运行时找同名的 `.ahk` 文件。

### 2. 验证编译产物

```powershell
# 关键验证：把 exe 复制到空目录运行，不应报 "Script file not found"
New-Item -ItemType Directory _test_isolated -Force
Copy-Item PopDrop.exe _test_isolated\
# 运行 --self-test（自测失败是已知问题，不影响正常启动，用来验证 EXE 是独立运行的）
_test_isolated\PopDrop.exe --self-test
Remove-Item _test_isolated -Recurse -Force
```

正确编译的 EXE 在空目录中能独立运行，不会报 "Script file not found"。

### 3. 准备配置文件

> **⚠️ 重要：`config.ini` 在开发过程中可能已是个人自用配置，包含本地路径、个人偏好等，不可直接分发！**
>
> **⚠️ 必须使用 `config.example.ini` 作为分发模板，且必须验证其中不包含任何个人路径（如 `C:\Users\...`）。**

| 文件 | 说明 |
|---|---|
| `config.ini` | **个人自用配置**，包含本地路径（如 `C:\Users\Forrest\...`），**禁止**直接打包 |
| `config.example.ini` | **分发模板**，打包时使用的标准配置，路径使用 `%USERPROFILE%` 等环境变量 |

注意：`config.example.ini` 的编码是 **UTF-16LE（BOM `0xFF 0xFE`）**，不是 UTF-8。修改时务必保持相同编码。

### 4. 打包发布

```powershell
# 创建目录结构
Remove-Item release -Recurse -Force
mkdir -p release/assets
mkdir -p release/native/bin/x64
mkdir -p release/native/bin/x86
mkdir -p release/native/third_party/pdfium

# 复制主程序
Copy-Item PopDrop.exe release\

# 复制 Helper（放到 native/bin/x64 和 native/bin/x86 下，不在根目录放）
Copy-Item native\bin\x64\PopDropTransfer.exe release\native\bin\x64\
Copy-Item native\bin\x64\PopDropPreview.exe release\native\bin\x64\
Copy-Item native\bin\x86\PopDropTransfer.exe release\native\bin\x86\
Copy-Item native\bin\x86\PopDropPreview.exe release\native\bin\x86\

# 复制配置 + 文档 + 图标 + PDFium 安装脚本 + 第三方许可
Copy-Item config.example.ini release\
Copy-Item README.md, USAGE.md, CHANGELOG.md, THIRD_PARTY_NOTICES.md release\
Copy-Item assets\* release\assets\
Copy-Item native\install-pdfium.ps1, native\pdfium-component.ini release\native\
Copy-Item native\third_party\pdfium\LICENSE release\native\third_party\pdfium\

# 打包为 ZIP
Compress-Archive -Path 'release\*' -DestinationPath 'release\PopDrop_v1.0.0.zip' -Force
```

## 编译踩坑记录

### 报 "Failed to compile" 但脚本自测通过

**根因：** 编译器目录的 `*.bin` 文件是 v1 版本，无法解析 v2 脚本。

**解决方法：** 使用 `/base` 参数直接指定 v2 解释器，不要替换 `.bin` 文件。

### 编译成功但运行报 "Script file not found"

**根因：** 把 `AutoHotkey64.exe` 改名为 `.bin` 后作为 Base 文件使用。`.bin` 后缀导致 Ahk2Exe 使用旧式资源名，v2 解释器无法识别，退化为普通解释器模式，运行时找同名的 `.ahk` 文件。

**解决方法：** 始终使用 `.exe` 后缀的 Base 文件，通过 `/base` 参数指定。

**验证方法：** 把 `PopDrop.exe` 复制到没有 `PopDrop.ahk` 的空目录运行，如果报 "Script file not found" 说明编译有问题。

### Git Bash 中编译失败

**根因：** MSYS2 自动转换 Windows 路径参数，导致 Ahk2Exe 收到错误参数。

**解决方法：** 使用 PowerShell 编译，或在 Git Bash 中设置 `MSYS2_ARG_CONV_EXCL='*'` 环境变量。

### 模块化后 --self-test 失败

`PopDrop.ahk` 中的 `--self-test` 参数分派在 `#Include modules/*.ahk` 之前，此时模块中的全局变量和函数尚未定义，导致自测失败。这是已知问题，不影响正常使用。

### Start-Process 数组参数导致 0x34 "Base file not found"

**现象：** 用数组形式传参调用 Ahk2Exe：

```powershell
Start-Process -FilePath 'C:\Program Files\AutoHotkey\Compiler\Ahk2Exe.exe' `
  -ArgumentList @('/in','PopDrop.ahk','/out','PopDrop.exe','/icon','assets\app.ico','/base','C:\Program Files\AutoHotkey\v2\AutoHotkey64.exe','/compress','0') -Wait
```

退出码 52（0x34），stderr 只打印 `Failed to compile: PopDrop.ahk`；但 `/base` 指向的 `AutoHotkey64.exe` 明明存在、自检也能跑通。

**根因：** Ahk2Exe 是 GUI 程序，`Start-Process` 用**数组形式**传参时，PowerShell 把数组元素按空格拼成一个命令行再交给进程；含空格的路径 `C:\Program Files\AutoHotkey\v2\AutoHotkey64.exe` 没有内嵌引号，被拆成 `C:\Program` 和 `Files\AutoHotkey\v2\AutoHotkey64.exe` 两段，Ahk2Exe 收到截断的 `/base` 值，因此报 0x34（Base file not found）。报错信息只提脚本名、不提 base 路径，极易误导。

**退出码对照（见 build.ps1）：** `0x03` 非法参数；`0x11` AHK 语法错误；`0x32` 无法打开脚本/include；`0x34` Base 文件未找到；`0x35` 图标未找到；`0x42` ICO 不可读；`0x45` 目标 EXE 正在运行/无法覆盖；`0x63`/`0x64` Ahk2Exe 指令非法/格式错。遇到 `Failed to compile` 先看退出码十六进制再定位。

**解决方法：** 用**单个字符串**作为 `-ArgumentList`，并对每个含空格的路径加双引号：

```powershell
$arg = '/in "PopDrop.ahk" /out "PopDrop.exe" /icon "assets\app.ico" /base "C:\Program Files\AutoHotkey\v2\AutoHotkey64.exe" /compress 0'
$p = Start-Process -FilePath 'C:\Program Files\AutoHotkey\Compiler\Ahk2Exe.exe' `
     -ArgumentList $arg -NoNewWindow -Wait -PassThru -RedirectStandardError err.txt
$p.ExitCode   # 0 = 成功
```

> 注意：`& '...\Ahk2Exe.exe' ...`（call 操作符）对 GUI 程序不会等待、也不设置 `$LASTEXITCODE`，无法可靠判断成败；需要退出码时一律用 `Start-Process -Wait -PassThru` + 单字符串参数。本仓库根 `build.ps1` 即采用这种单字符串形式，可直接参考其拼装方式。

### build.ps1 验证门禁会阻塞编译

根 `build.ps1` 在编译前会先跑 AHK `--self-test` 和 Python 回归测试，任一失败即 `exit 11`/`exit 12` 中止，不会执行编译。由于上文“模块化后 --self-test 失败”仍存在、Python 测试也有过时断言，`build.ps1` 目前会卡在自检步直接退出。需要编译时按本文档第 1 步直接调用 Ahk2Exe；待自检与 Python 测试修复后再用 `build.ps1` 做端到端验证。

## 注意事项

- **编译前确保关闭正在运行的 `PopDrop.exe` 进程。**
- `PopDrop.exe` 和 `config.ini` 必须放在同一目录。
- 不要把 x86 helper 与 x64 主程序混用。启动时 helper 版本握手会拒绝不兼容组件。
- 如果旧 `config.ini` 有未提交的个人修改，备份后再覆盖。
- 杀毒软件可能误报 `PopDropPreview.exe`，需要恢复。
